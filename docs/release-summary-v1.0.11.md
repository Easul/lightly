# v1.0.11 完整更新说明

本文汇总 `v1.0.10` 之后进入 Lightly 的功能与修复。重点是新增音乐播放器，以及
YouTube 长视频解析、浮动视频播放体验和发布供应链的改进。

## 一、用户可见变化

### 1. 音乐播放器

Lightly 新增音乐播放器，覆盖在线与本地两条链路：

- 支持手动配置音乐 API 基础地址，自动归一化常见输入格式，并对鉴权失败给出明确错误。
- 在线音乐支持搜索、按歌手/专辑等分组浏览和多种播放模式。
- 播放状态进入系统通知栏，锁屏/后台也能控制；切换网络或重新进入时支持恢复播放。
- 在线曲目可下载到本地音乐库，文件名规范为“歌手-标题”，同标题曲目自动区分来源。
- 下载和刷新过程保留封面、歌词与歌手/专辑等元数据；同一曲目存在多个 remote-id 副本时
  元数据会合并保留。
- 本地音乐支持自然排序、批量删除、断点续播提示和统一的播放队列。

### 2. 浮动视频播放器手势

- 左侧区域双击快退 5 秒，右侧区域双击快进 5 秒。
- 在画面上横向拖动可实时预览目标时间点，松手后才执行跳转，拖动距离与目标时间有明确
  对应关系，避免拖得过多或过少。
- 长按画面进入 3 倍速播放，松开后恢复原速。
- 双击画面中央进入小窗模式；小窗只保留一个关闭按钮，进度条、按钮等不再挤在一起。
  再次双击小窗恢复完整控制界面。
- 视频时长超过 1 小时时，进度与时长正确显示小时位。

## 二、YouTube 解析修复

配套 `yt-resolver` 子仓库（`v0.0.4`）修复了多个解析可靠性问题：

- **长视频只解析出一部分**：GoogleVideo 对长视频常返回按 Range 分段的可播放候选。此前
  resolver 会把某个中间分段的 URL 当作完整结果，播放器只能播约半小时。现在会把捕获到的
  分段请求归一化为覆盖完整时长的可用候选，并在缺少时长信息时拒绝提前返回。
- **20 秒预算超时**：已解析过的 watch 页面会缓存并复用页面结果；解析轮询跨越 watch 页
  内导航继续工作，避免一次导航重置就耗尽整个预算。
- **解析次数多后失败**：Google Sorry 验证页只在 watch 主导航阶段判定，嵌入的验证/风控
  资源（如验证码图片、统计请求）不再把整个解析判定为被拦截。
- **诊断可观测但不泄密**：时长、候选数量等诊断日志有界，且不输出 Cookie、完整签名 URL
  等敏感内容。

## 三、发布供应链

本版本依赖新的 `yt-resolver` AAR。Lightly Release 工作流继续通过
`YOUTUBE_RESOLVER_AAR_URL` 与 `YOUTUBE_RESOLVER_AAR_SHA256` 两个 Actions 变量固定
AAR 来源并在构建前校验哈希：

- 发布 `v1.0.11` 前必须先把这两个变量指向 `yt-resolver` `v0.0.4` Release 的
  `yt-resolver.aar` 与其 `SHA256SUMS` 中的哈希。
- 不复用 `v1.0.10` 对应的旧 AAR/哈希，否则长视频解析修复不会进入正式包。
- companion（Telegram / WebRTC / EasyTier）未变化时继续复用已发布的 `plugins.json`。

## 四、验证范围

- 浮动视频手势、小时时长显示和小窗模式均有针对组件与手势数学的单元测试。
- `yt-resolver` 侧覆盖了分段捕获归一化、页面缓存复用、Sorry 判定范围与导航轮询。
- Release CI 继续执行 AAR 哈希校验、companion ABI/签名检查和最终 APK 构建。
